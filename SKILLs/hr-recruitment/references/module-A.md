## Positioning

Module A is the **infrastructure layer** for the entire skill. It operates independently of JD content (except A-S5) and produces the structured data that Module B and C depend on. Every resume gets the same treatment regardless of the position being hired for.

## Input & Scale

- **Source:** `resumes/` directory — PDF, DOCX, DOC, JPG, PNG files
- **JD reference:** `jd.md` — used only for A-S5 misclassification detection
- **Typical batch:** 10-30 resumes per run（大batch 61+ 也可，每次一份原子处理）
- **Output location:** `skill-output/A-parse/`

## 并行处理架构

当简历数量 > 4 份时，启动批次并行模式。完整架构和调度规则见 `references/parallel-processing.md`。

**核心约定（本节补充细节）：**

### 子 Agent 模型一致性（强制）

所有子 agent **必须与主 agent 使用相同的模型和配置**，不得降级。原因：
- A-S2→A-S5 的推理质量（院校归一化、水分分析、质量评分）强依赖于模型能力
- 主子 agent 使用不同模型会导致不同简历之间评分标准不一致，跨简历比较结论不可信

### 子 Agent 的工作边界

- **工作目录**：仅限自己的 `batch{n}/` 目录
- **不写入** A.worklist.md（由主 agent 审核后统一更新）
- **不调用** `track_complete.py`（由主 agent 在审核通过后调用）
- 子 agent 处理完一份简历后，在回复中报告进度；处理完全批后，回复汇总

### ⚠️ 强制 LLM 精析原则（禁止批量脚本）

A-S2→A-S5 步骤**必须由 LLM 对每份简历逐一进行精确分析推理**，严禁批量评分脚本：
- A-S2 信息提取归一化需要语义理解（如区分"北大"是北京大学还是台北大学）
- A-S3 水分检测需要逻辑推理（"增长200%"是否可疑需要上下文）
- A-S4 质量评分需要整体内容评价
- **不要写任何批量脚本**来做 A-S2→A-S5 的分析工作
- A-S1 文本提取和代码写入可以脚本化（纯机械操作）

## A-S1: Text Extraction & Raw Text Write

A-S1 完成两件事：① 提取文字；② **用代码**将原始文本写入 `analysis.md` 的第一节。两步均由脚本/代码完成，不消耗 LLM token。

### 决策树

```
File type?
├── PDF
│   ├── Use LobsterAI official pdf skill (pypdf) to extract text
│   │   ├── Got valid text (length > 50 chars, not garbled) → SUCCESS
│   │   └── Empty / garbled / pure image pages (pypdf 提取失败)
│   │       → 检查当前模型是否具备多模态（视觉）能力
│   │       ├── 模型具备多模态能力
│   │       │   → 直接用 `read` 工具读取原始 PDF 文件（模型视觉直接处理）→ SUCCESS
│   │       │   → 若 read PDF 仍失败 → mark ❌ and move on
│   │       └── 模型不具备多模态能力
│   │           → 直接 mark ❌，放弃自动化处理该简历，记录原因
│   └── Record extraction method: "pdf解析" or "视觉直接处理(PDF)"
│
├── Word (DOCX/DOC)
│   ├── Use LobsterAI official docx skill to extract text → SUCCESS
│   └── Record extraction method: "docx解析"
│
└── Image (JPG/PNG)
    ├── Feed directly to model vision channel (read tool)
    └── Record extraction method: "视觉直接处理"
```

### 提取成功后：代码写入 analysis.md 第一节

提取完文字后，**立即用 Python 代码**（文件 I/O，非 LLM write 工具）将原始文本写入 `A-parse/{filename}.analysis.md`：

```python
import datetime, os

raw_text = "..."          # 上一步提取的完整文字
method   = "pdf解析"      # 提取方式
src_file = "resumes/张三.pdf"
out_path = "skill-output/A-parse/张三.pdf.analysis.md"

header = f"""## 原始文本

- 源文件：{src_file}
- 提取方式：{method}
- 提取时间：{datetime.datetime.now().strftime('%Y-%m-%d %H:%M')}
- 字符数：{len(raw_text)}

---

{raw_text}

---

<!-- LLM 分析内容从此处开始 -->
"""

with open(out_path, "w", encoding="utf-8") as f:
    f.write(header)
```

写入完成后，LLM 接手：读取该文件，在 `<!-- LLM 分析内容从此处开始 -->` 之后追加 A-S2～A-S5 的分析内容。

### 图片型 PDF 视觉处理约束（强制）

**强制禁止（违反即为执行错误）：**
- ❌ 禁止调用 `pdf_to_png.py` 或任何 PDF → 图片转换逻辑
- ❌ 禁止使用任何本地 OCR 算法（Tesseract/easyocr/paddleocr 等）
- ❌ 禁止 `pip install pymupdf`、`pdf2image`、`Pillow`、`wand` 等
- ❌ 禁止生成任何临时图片文件（.png/.jpg/.ppm/.bmp）作为中间产物

### Dependency: LobsterAI Official PDF Skill

**Module A 启动前，必须先确认 pdf skill 已在当前 session 中启用。**

检查方式：尝试 `from pypdf import PdfReader`。若导入失败：
- **不要尝试 `pip install pypdf`**
- 告知用户："请在 LobsterAI skill 面板中手动勾选 **pdf skill**，完成后告知我，再继续处理简历。"
- 等待用户确认后重新检查，确认通过再执行 A-S1

pdf skill 启用后，使用以下代码提取 PDF 文本（hr-recruitment-skill 自带，无需调用其他脚本）：

```python
from pypdf import PdfReader

reader = PdfReader("path/to/resume.pdf")
full_text = ""
for page in reader.pages:
    text = page.extract_text() or ""
    full_text += text + "\n"
```

**提取结果验证：**
- 提取文本长度 ≥ 50 字符，且无明显乱码（无大量 `\x00`、`(cid:XX)`、连续非 CJK 非 ASCII 符号）→ 视为成功
- 否则视为提取失败 → 进入多模态判断分支（见上方决策树）

For the complete pdf skill reference, see `~/AppData/Roaming/LobsterAI/SKILLs/pdf/SKILL.md`.

**Validation after extraction:**
- If extracted text length < 50 chars, or text appears garbled (high ratio of replacement characters / undecodable sequences), treat as extraction failure → fall through to vision fallback.
- Common garbled patterns: consecutive `\x00`, `(cid:XX)` sequences, or text that is mostly non-CJK non-ASCII symbols.

### Dependency: LobsterAI Official DOCX Skill

**Module A 启动前，必须先确认 docx skill 已在当前 session 中启用。**

检查方式：尝试 `from docx import Document`。若导入失败：
- **不要尝试 `pip install python-docx`**
- 告知用户："请在 LobsterAI skill 面板中手动勾选 **docx skill**，完成后告知我，再继续处理简历。"
- 等待用户确认后重新检查，确认通过再执行 A-S1

For the complete docx skill reference, see `~/AppData/Roaming/LobsterAI/SKILLs/docx/SKILL.md`.

### Model Vision Channel

当图片型 PDF 经 pypdf 提取失败，且当前模型具备多模态能力时，直接用 `read` 工具读取原始 PDF 文件，由模型视觉能力一次性完成 OCR 和内容识别。无需独立的 OCR 步骤。对于独立图片文件（JPG/PNG），同样直接 `read` 送入模型视觉处理。

**此路径仅在模型具备多模态能力时可用。模型不具备多模态能力时，直接标记 ❌，不做任何额外处理。**

### 绝对禁止本地 OCR（任何情况均适用）

- 严禁使用 Tesseract、easyocr、paddleocr、pytesseract 等任何本地 OCR 算法
- 严禁将 PDF 转换为图片（PNG/JPG/PPM/BMP 等）后再处理
- 严禁调用 `pdf_to_png.py` 或类似的 PDF→图片转换脚本
- 严禁 `pip install pymupdf`、`pdf2image`、`Pillow`、`wand` 等图像处理库

以上禁止规则**无例外**，不因文件类型、模型能力或任何其他条件而豁免。

### A-S1 Completion

- 代码写入 `A-parse/{filename}.analysis.md` 原始文本节（见上方代码示例）
- Append to A.log.md: filename, extraction method, status, character count
- If extraction **fails**: mark ❌ with reason, record in alerts, skip A-S2 through A-S5 for this file

## A-S2: Information Extraction & Normalization

Extract structured fields from the raw text (or vision result). Every field gets a **confidence level** annotation.

### 置信度等级定义

| 等级 | 含义 | 使用场景 |
|------|------|----------|
| **高** | 信息明确、完整、无歧义，可直接采信 | 简历中清晰陈述的字段 |
| **中** | 信息存在但不完整，或需要推断。HR 应留意 | 从上下文推断、缩写、部分呈现 |
| **低** | 信息缺失、矛盾或可疑。**必须注明具体原因** | 数据缺失、存在冲突、可疑模式 |

### Field Schema

#### 基本信息

| 字段 | 高 | 中 | 低 |
|------|------|--------|-----|
| 姓名 | 明确标注 | 从邮箱/文件名推断 | 无法确定 |
| 性别 | 明确标注 | 从姓名推断（需注明） | 无法确定 |
| 年龄/出生年月 | 明确标注 | 从毕业年份推算 | 无信息 |
| 手机号 | 完整号码 | 格式异常/部分遮挡 | 未找到 |
| 邮箱 | 完整邮箱 | 格式异常 | 未找到 |

#### 教育背景（每条记录独立评级）

| 字段 | 高 | 中 | 低 |
|------|------|--------|-----|
| 院校名称 | 全称 | 简称/缩写 | 缺失 |
| 学历层次 | 明确标注（本科/硕士/博士/专科） | 仅有校名无学历 | 可疑（隐藏专升本、模糊表述如"大学毕业"） |
| 专业 | 明确标注 | 从课程/经历推断 | 缺失 |
| 起止时间 | 完整年月 | 仅有年份 | 缺失 |

##### 高校归一化校验（精细化规则）

在提取教育背景时，**必须**对每段教育经历独立进行归一化校验。参照 `references/university-ranking.md` 中的完整数据进行以下操作。

**核心原则：学历阶段独立评价**

本科、硕士、博士**各自独立评价**，不可合并计算院校层级。同一个学校的本科和硕士含金量不同——通常认为**本科阶段的院校层次更反映学术基础**，硕士阶段含金量相对弱于本科阶段。因此在：
- structured.md 中，每段教育经历独立列出层次标注
- analysis.md 中，每段教育经历独立列出置信度+层次标注
- A-S4 评分中，本科院校权重为 65%，硕士院校权重为 35%，博士院校权重单独加分
- A-S3 水分分析中，本科院校层次异常比硕士院校层次异常更严重

**1. 名称归一化**
- 将简称/缩写/俗称统一为官方全称（如"北大"→"北京大学"，"HKUST"→"香港科技大学"）
- 使用 `university-ranking.md` 第四节"常见高校简称对照表"进行匹配
- 归一化后的名称写入结构化字段，原始写法保留在备注中
- **对海外高校**：在归一化名称后标注国家/地区，格式为 `{官方全称}（{国家简称}）`
  - 国家简称示例：（美）、（英）、（澳）、（加）、（新）、（港）、（法）、（德）、（日）、（韩）等
  - 使用 LLM 自身知识进行国家判断，无需查表
  - 示例：`西北大学（美）`、`伦敦大学学院（英）`、`香港大学（港）`、`悉尼大学（澳）`

**2. 院校层次标注（国内/海外分离）**

**国内高校**：依据以下数据源逐级判定并标注：
- **985**：是否在 985 工程 39 所名单内
- **211**：是否在 211 工程 112 所名单内（所有 985 均为 211）
- **双一流**：是否在第二轮双一流建设 147 所名单内
- **普通本科 / 专科**：不在以上名单内
- 标注格式：`985 / 211 / 双一流` 或 `211 / 双一流` 或 `双一流` 或 `普通本科`
- 使用 `query_ranking.py` 脚本查询 `university-ranking.md` 获取准确层次。对于知名院校（北大/清华/人大/复旦等），可用 LLM 自身知识辅助判断。

**海外高校**：标注 QS 排名区间，使用 LLM 自身知识判断：
- QS Top 30 / Top 50 / Top 100 / Top 200 / Top 500 / 500+或未上榜
- 同时参考 2024、2025、2026 三年排名，取最优排名作为标注依据
- 标注格式：`QS={区间}`，如 `QS=Top 50`、`QS=Top 100`
- 使用 LLM 自身知识进行 QS 排名判断，对于不确定的学校调用 `query_ranking.py` 查表辅助
- **特别说明**：海外高校不标注 985/211/双一流（这些标签仅适用于中国大陆高校）

**港澳台高校**：
- 同时标注 QS 排名（LLM 知识判断）+ 是否等同于国内 985/211 层次（仅作参考）
- 标注格式：`QS=Top 30，层次参考：985` 或 `QS=Top 100，层次参考：211`

**3. 学历完整度校验**
对每段教育经历检查学历信息完整性：
- **学制长度**：本科正常4年（医学等5年）、硕士正常2-3年、博士正常3-5年
  - 本科2年或3年 → 疑似专升本，标记 ⚠️
  - 硕士1年（英国/香港等一年制授课型硕士）→ 正常，但标注学制
- **入学年龄**：本科入学年龄一般在17-20岁
  - 25岁以上入读本科 → 可能有前序学历未披露
- **起止时间**：完整年月为高置信度，仅年份为中置信度

**4. 候选人自述校验**
候选人可能对自己学校的层次描述不准确，需要校验：
- **虚报**：声称"985高校"但查表发现不是 → 标记为教育信息风险点
- **错标**：写了"211"但实际是普通双一流（非211）→ 修正标注
- **漏标**：未提及学校层次但实际是 985/211/双一流 → 补充标注
- **名称错误**：写的学校名称无法匹配任何已知高校（可能笔误或虚构）→ 低置信度 + 风险标记

**5. 输出格式（每段教育经历独立）**

在 structured.md 的教育背景部分，每段教育经历独立列出：
```markdown
### 教育经历 1（本科）
- 院校（归一化）：北京大学
- 院校（原始）：北大
- 院校层次：985 / 211 / 双一流
- 海外QS排名：—（国内高校）
- 学历层次：本科
- 专业：计算机科学与技术
- 起止时间：2019.09 – 2023.06
- 学制完整性：✅ 正常（4年制）
- 校验结果：✅ 信息一致

### 教育经历 2（硕士）
- 院校（归一化）：哥伦比亚大学（美）
- 院校（原始）：Columbia University
- 院校层次：—（海外高校）
- 海外QS排名：QS=Top 30
- 学历层次：硕士
- 专业：数据科学
- 起止时间：2023.09 – 2024.12
- 学制完整性：✅ 正常（1.5年制授课型硕士）
- 校验结果：✅ 信息一致
```
在 analysis.md 的教育背景部分，每段教育经历增加层次和校验行：
```markdown
- 院校：北京大学 [置信度：高]
- 院校（归一化）：北京大学 [985 / 211 / 双一流]
- 国外QS排名：—
- 学历：本科 [置信度：高]
- 专业：计算机科学与技术 [置信度：高]
- 时间：2019.09 – 2023.06 [置信度：高]
- 校验结果：✅ 信息一致
```

**6. 与 A-S3 联动**
校验中发现的虚报、错标、名称错误等问题，同时计入 A-S3"学历水分"维度的风险评估。本科阶段的问题严重度高于硕士/博士阶段。

#### 工作/实习经历（每条记录独立评级）

| 字段 | 高 | 中 | 低 |
|------|------|--------|-----|
| 公司名 | 公司全称 | 简称/缩写 | 缺失 |
| 职位 | 明确标注 | 从描述推断 | 缺失 |
| 起止时间 | 完整年月 | 仅有年份或"至今" | 缺失 |
| 职责描述 | 具体且有量化数据 | 有描述但笼统 | 一句话或缺失 |

#### 项目经历（每条记录独立评级）

| 字段 | 高 | 中 | 低 |
|------|------|--------|-----|
| 项目名 | 明确标注 | 从描述推断 | 缺失 |
| 角色 | 明确标注 | 从描述推断 | 缺失 |

| 成果描述 | 量化数据 + 具体结果 | 有描述但笼统 | 缺失 |

#### 技能清单

| 字段 | 高 | 中 | 低 |
|------|------|--------|-----|

#### 时间线

| 高 | 中 | 低 |
|------|--------|-----|
| 连续无重叠、无未解释的空窗期 | 合理空窗（如全日制学习期间） | 重叠或无解释的空窗 |

## A-S3: 简历水分分析（Inflation & Fraud Detection）

对 A-S2 提取的结构化数据进行深度水分分析。本步骤的核心理念：**简历几乎不存在完全无水分的情况，关键在于识别水分的类型、程度和模式，为 HR 提供具体、可操作的判断依据。**

### 适用场景区分

简历水分的表现形式因候选人阶段不同而差异巨大：

| 类型 | 常见水分模式 | 典型特征 |
|------|------------|----------|
| **校招/实习** | AI生成痕迹、夸大项目角色、虚构个人项目成果、经历时间重叠 | 经历少但描述华丽、大量"从0到1"表述、3个月实习声称主导系统级项目 |
| **社招** | 夸大职位层级、虚报业绩数字、延长/合并工作年限、合并跳槽经历、虚构领导角色、夸大项目规模 | 管理性词汇与实际动作不匹配、业绩无基数、时间线拼接痕迹 |

**自动判断**：根据候选人教育背景推算毕业年份，若距今 ≤ 2年或仍在读，按校招/实习模式分析；否则按社招模式分析。两种模式的水分类型有交叉，全部扫描后按实际命中输出。

### 水分类型体系

#### 类型1：夸大职位层级（社招为主）

**常见手法**：把"参与""协助"写成"负责""主导"，把"主管"写成"经理"，把"区域"写成"全国"。

**典型案例**：原简历写"作为项目经理，主导公司A级项目，管理5人团队"；实际只是项目组普通成员，团队5人并非其管理，只是协作关系。

**识别逻辑**：

1. **动词一致性检验**：简历声称"管理X人团队"，但职责描述中只出现"协作""配合""沟通"等平级动词，未出现"下属考核""绩效面谈""招聘需求""预算审批"等管理专属动作 → 前后矛盾
2. **层级链合理性**：若同时写"向XX总监汇报"且自己也是"经理"，检查是否存在合理的组织层级链。社招中经理级以上通常会明确写出汇报上级
3. **年限-级别匹配**：3年经验自称"全国XX负责人"极不合理（全国级岗位一般需8年以上）；5年经验即"VP"在非创业公司不合理
4. **职位抬头与职责的匹配**：抬头写"高级经理"但描述全是执行层工作（制作PPT、整理数据、跟进排期），无任何策略/决策/资源配置类描述

**输出标注格式**：
```
⚠️ 水分类型：夸大职位层级
  位置：[第X段经历 - 公司名]
  疑点：声称"管理5人团队"，但职责描述仅含"协作""沟通"等平级动词，无管理专属动作
  严重度：中
  建议验证：背调时确认汇报关系和实际职级
```

#### 类型2：夸大业绩数字（社招为主，校招亦有）

**常见手法**：把部门整体业绩写成个人贡献，用模糊大数字（"提升200%""节约500万"）但不给基数，多段经历重复使用极端增长值。

**典型案例**：原简历写"负责华东区销售，年度业绩增长200%，超额完成目标"；实际该区域上年基数极低（从10万增长到30万），且增长主要靠公司整体品牌拉动而非个人能力。

**识别逻辑**：

1. **无基数的增长率**：写"增长200%"但未提供基数和绝对额 → 标记为"不可验证的增长声称"（从10万到30万也是200%）
2. **人均产出常识校验**：声称"团队5人，年销售额增长200%"，可推算人均产出，与行业平均对比。普通销售人均年产100-200万，若人均不足50万却称增长200%则可疑
3. **多段极端数值模式**：同一份简历中3+段经历都出现"增长50%以上"或"提升XX%"且不解释市场/产品变化，大概率为系统性美化
4. **归因合理性**：写"个人独立完成XX万业绩"，但同时提到团队协作、部门支持，个人贡献无法量化分离
5. **校招特化**：实习3个月声称"带来XX万增长""用户增长XX万"，需考虑实习生通常不独立负责核心指标

**输出标注格式**：
```
⚠️ 水分类型：夸大业绩数字
  位置：[第X段经历 - 具体描述]
  疑点：声称"业绩增长200%"，未提供基数，无法验证实际规模
  严重度：低/中/高
  建议验证：面试追问绝对数值和个人vs团队贡献分离
```

#### 类型3：延长/合并工作年限（社招）

**常见手法**：把两段工作之间的空窗期合并进某一公司，把试用期未过的短经历隐去，使工龄看起来连续。

**典型案例**：原简历写"2018.06 – 2023.08 某科技公司 高级工程师"；实际2018.06–2019.12在该公司，2020.01–2020.06空窗，2020.07–2023.08在另一家公司，两段经历被合并为一段。

**识别逻辑**：

1. **精确无缝衔接**：前一段结束和下一段开始精确到同一个月（如2021.05结束-2021.05开始），现实中离职和入职通常有间隔（1-4周），精确无缝需警惕
2. **教育时间重合**：某段工作时间与脱产读研/读博时间完全重合 → 明显矛盾
3. **只标年不标月**：刻意模糊时间精度（"2019-2022"而非"2019.03-2022.06"），可能隐藏空窗
4. **工作时长与公司年限矛盾**：声称在某司工作5年，但该公司成立仅3年（可通过公司名和公开信息交叉验证）
5. **职责描述风格断裂**：同一段经历前期描述风格（基础执行）和后期（战略决策）差异明显，可能是两段不同公司经历被合并

**输出标注格式**：
```
⚠️ 水分类型：延长/合并工作年限
  位置：[第X段经历与第Y段经历之间]
  疑点：两段经历精确无缝衔接（2021.05-2021.05），现实中通常有间隔
  严重度：低
  建议验证：背调确认实际入离职日期
```

#### 类型4：合并跳槽经历（社招）

**常见手法**：把多段短期（<6个月）的频繁跳槽经历合并成一段较长经历，隐去中间公司名称。

**典型案例**：原简历写"2019.04 – 2022.09 某互联网公司 运营经理"；实际中间还经历过另外两家公司，每段时间不足6个月，被全部隐去，合并为一段连续经历。

**识别逻辑**：

1. **时间跨度与经历数量不匹配**：6年时间内列出4段经历，但累计月数明显短于总时间跨度（如2016–2022共7年，但列出经历总月数只有60个月）→ 存在隐藏空窗或被合并的公司
2. **单段超长但职责断裂**：某段经历特别长（5年+），但职责描述前后风格差异大（前2年基础执行 → 后3年战略决策），可能是两段不同公司被合并
3. **掩饰性语言**：出现"期间曾借调""参与外部项目""兼任XX"等模糊措辞，可能是隐藏中间经历的痕迹
4. **职位跳跃不连贯**：同一公司内从"助理"直接到"总监"且无中间过渡，可能是合并了中间在其他公司的经历

**输出标注格式**：
```
⚠️ 水分类型：合并跳槽经历
  位置：[第X段经历]
  疑点：该段经历时长5年，但职责描述前后风格断裂（前期执行层面 vs 后期决策层面）
  严重度：中
  建议验证：面试追问该时段内的具体角色变化和晋升路径
```

#### 类型5：虚构领导角色与下属人数（社招为主）

**常见手法**：把平级协作或跨部门配合描述为"带领""管理""培养"，虚报下属人数。

**典型案例**：原简历写"管理10人团队，负责团队绩效考核与招聘"；实际只是项目制中临时协调过10个人，没有行政汇报关系和考核权。

**识别逻辑**：

1. **管理动作缺失**：写"管理10人"，但从未出现"绩效评估""晋升提名""离职面谈""预算审批"等管理专属职责，只有"分配任务""跟踪进度"等协调性动作 → 大概率是项目协调而非管理
2. **人数-职级-年限三角校验**：
   - 2年经验、无管理层抬头，却写管理10人 → 极不合理
   - 5年经验、经理级、管理10人 → 合理范围
   - 3年经验、主管级、管理3-5人 → 合理范围
3. **汇报关系逻辑**：写"向副总裁汇报"且"管理10人"，但无中间层级（总监/高级经理），直接跨级汇报在正规公司较少见
4. **管理 vs 协调的关键区分词**：
   - 真正管理：绩效考核、晋升推荐、编制申请、人力预算、1:1 沟通、PIP
   - 仅协调：分配任务、跟进进度、组织会议、对齐目标、拉通需求

**输出标注格式**：
```
⚠️ 水分类型：虚构领导角色
  位置：[第X段经历 - "管理10人团队"]
  疑点：声称管理10人，但描述中仅有协调类动作（分配任务、跟踪进度），无管理专属职责
  严重度：中
  建议验证：面试追问"请描述一次你对下属的绩效反馈"
```

---

#### 类型6：夸大项目角色与规模（社招+校招均常见）

**常见手法**：把参与边缘模块写成核心架构，把百万级项目写成千万级，把外包人员工作写成自有团队成果。

**典型案例**：原简历写"主导公司核心交易系统重构，项目预算2000万，团队20人"；实际只负责其中一个子模块的测试文档编写，项目实际预算200万。

**识别逻辑**：

1. **角色与任务颗粒度矛盾**：写"主导"但描述中只有"参与需求讨论""编写部分文档"等低阶任务 → 角色与实际贡献不匹配
2. **预算数字可疑**：项目预算过于整齐（2000万、5000万）且无来源说明；中小企业出现"国家级项目""全行业标杆"等宏大措辞
3. **人员角色定位模糊**：写"团队20人"但未说明自己的位置（是"带领20人"还是"20人之一"），社招简历中成熟候选人通常会明确区分
4. **校招特化识别**：
   - 实习3个月声称"从0到1搭建XX系统" → 3个月完成系统级工程几乎不可能
   - "主导"级别描述，但身份为实习生/初级 → 身份与角色矛盾
   - 课程项目或Kaggle比赛包装成"公司项目" → 看是否有公司名、是否有上线/投产描述

**输出标注格式**：
```
⚠️ 水分类型：夸大项目角色与规模
  位置：[第X段/项目名]
  疑点：声称"主导核心系统重构"，但描述仅涉及文档编写和测试
  严重度：中/高
  建议验证：面试追问"请详细描述你个人负责的具体模块和代码/产出"
```

#### 类型7：AI生成 / 模板化简历（校招+社招均有）

**常见手法**：使用 ChatGPT/文心等工具直接生成简历内容，或套用高度同质化的简历模板。

**典型案例**：一份应届生简历中三段实习经历全部使用"负责XX模块的开发与优化，通过引入XX技术，实现了XX%的性能提升"的统一句式，且每段都恰好提升30%、40%、50%，无任何个性化细节。

**识别逻辑**：

1. **句式高度统一**：多段经历均使用相同结构（"负责...，通过...，实现了..."），缺乏个人表达差异
2. **关键词堆砌**：技能列表异常全面，远超该年限/层级正常掌握范围
3. **缺乏个性细节**：没有具体工具名、版本号、具体人名、具体日期等"只有亲历者才知道"的细节
4. **行文过于流畅完美**：全篇无错别字、无口语化表达、无任何瑕疵，不符合真实手写简历特征
5. **数字过于规整**：所有业绩数字都是整数百分比（提升30%、增长50%、优化40%），现实数据很少如此整齐

**输出标注格式**：
```
⚠️ 水分类型：AI生成/模板化
  位置：[全篇 / 第X-Y段经历]
  疑点：三段经历句式完全一致（"负责...通过...实现了..."），数字均为整十百分比，缺乏个性化细节
  严重度：中
  建议验证：面试中要求脱稿描述某段经历的具体过程和踩过的坑
```

#### 类型8：学历水分（校招+社招均有）

**常见手法**：隐藏专升本/自考/成人教育背景，虚报院校层次，模糊学历性质。

**典型案例**：简历仅写"XX大学 本科 计算机科学"，实际为专科毕业后通过成人自考获得本科学历，刻意省略专科阶段和学历性质。

**识别逻辑**：

1. **已在 A-S2 高校归一化中覆盖**：虚报985/211、简称误导（如用"北师"实为UIC而非北京师范大学）等已在 A-S2 标记
2. **补充检查**：
   - 学制异常：本科3年（正常4年）或2年（可能为专升本）
   - 只写最高学历不写前序：硕士写了但本科完全不提 → 可能隐藏非全日制本科
   - 入学时间与年龄不匹配：25岁入读本科 → 可能有前序学历未披露
   - 同等学力/非全日制标记缺失

**输出标注格式**：
```
⚠️ 水分类型：学历水分
  位置：[教育背景部分]
  疑点：本科学制仅2年（2019.09-2021.06），疑似专升本但未注明前序专科经历
  严重度：中
  建议验证：要求提供完整学历证明，确认学历性质（全日制/自考/成教）
```

### 校招/实习场景的特殊水分模式

对于在校生和应届生，除上述通用类型外，额外关注：

| 模式 | 识别逻辑 |
|------|----------|
| **实习时间重叠** | 两段实习时间有交叉，且非明确兼职 → 可能虚构其中一段 |
| **个人项目无法验证** | 声称"独立开发XX产品，用户XX万"但无可查证链接、无上架记录 → 标记为不可验证 |
| **课程项目包装** | 没有公司名、没有上线描述、时间与学期吻合 → 大概率是课程作业包装 |
| **竞赛成果夸大** | "国家级"竞赛但实际为校企联合举办的商业赛事 → 核实赛事级别 |
| **实习密度不合理** | 大三一年有4段实习且每段1-2个月 → 频繁跳槽或部分虚构 |

- 命中水分类型数：X

- 水分严重度分布：高X项 / 中X项 / 低X项

每个识别到的水分点按以下格式输出：

```markdown

```

#### 3. 综合可信度评分规则

基础分 100，逐项扣减：

| 严重度 | 单项扣分 | 说明 |
|--------|----------|------|
| 低 | -3~5 | 常见美化，不影响整体判断 |
| 中 | -8~12 | 存在实质性夸大，需要面试验证 |
| 高 | -15~25 | 核心信息可能虚构，建议重点核实 |

最低分为 0，不出现负数。

#### 4. 水分模式总结

在所有水分点列出后，给出1段总结性评价（2-4句），描述：
- 该候选人的水分整体模式（系统性美化 / 个别夸大 / 基本真实）
- 水分集中在哪些维度（业绩 / 角色 / 时间线 / 学历）
- 对HR决策的建议（需重点验证什么、是否值得进入面试）

---

### 重要原则

1. **永远不自动淘汰**：即使可信度评分为 10/100，仍完整呈现给 HR。所有判断仅供参考。
2. **区分"美化"和"虚构"**：适度美化是简历的常态（选择性呈现优势），只有实质性虚构才是高严重度。
3. **给出验证建议**：每个水分点都要附带具体的验证方式，让 HR 在面试中有针对性地追问。
4. **上下文敏感**：同样是"增长100%"，在创业公司早期合理，在成熟企业则需要更多解释。
5. **实习生宽容度**：校招/实习候选人的"夸大"容忍度应高于社招，因为经历有限，适度包装属于行业常态。

## A-S4: Quality Scoring

Five dimensions, each 0-20 points, max 100. This is a **pure resume quality assessment**, independent of JD.

### 评分细则

Refer to `references/university-ranking.md` for 985/211 complete lists and QS rankings to identify which tier a school belongs to.

#### 教育背景（0-20分）—— 学历阶段独立评分

**核心原则**：本科、硕士、博士各自独立评价其院校层次。本科阶段权重最高（占教育背景分的65%），因为高考筛选度远高于考研/申请。

**单学历候选人**（只有本科或只有硕士）：

| 院校层级 | 分数范围 |
|---------|---------|
| 国内985 / 海外QS Top 30 | 16-18 |
| 国内211（非985）/ 海外QS Top 100 | 13-15 |
| 国内双一流（非211）/ 海外QS Top 200 | 10-12 |
| 普通本科 / 海外QS Top 500 | 7-9 |
| 专科 / 海外QS 500+或未上榜 | 4-6 |
| 信息缺失 | 0-3 |

**多学历候选人**（本科+硕士，或本科+硕士+博士）：

教育背景分 = 本科分（权重65%）+ 硕士/博士加分（权重35%），上限20分。

计算方法：
1. **本科院校打分**（base 分数）：按上表单学历标准给出本科分数
2. **硕士加分**：硕士院校比本科高1档 → +2；同档 → +1；低1档 → +0
3. **博士加分**：有博士学位 → +3（独立加分，不受硕士影响），上限20
4. **上限 20 分**

**跨体系档位比较规则（国内与海外高校混合时）：**

当本科与硕士分属国内/海外不同体系时，使用以下对照换算档位差：

| 国内档位 | 等效海外档位（参考） |
|--------|----------------|
| 985 | QS Top 50 |
| 211（非985）| QS Top 100–200 |
| 双一流（非211）| QS Top 200–500 |
| 普通本科 | QS Top 500 / 未上榜 |

示例：本科普通本科（国内），硕士 QS Top 100（海外）→ 海外硕士等效"211档"，比普通本科高1档 → +2。
本科985，硕士 QS Top 30（海外）→ 海外硕士等效"985档"，同档 → +1。

示例：
- 南昌大学本科（211，14分）+ 北京大学硕士（985，top档）→ 14 + 2（跨档提升）= 16分
- 北京大学本科（985，18分）+ 北京大学硕士（985，同档）→ 18 + 1 = 19分
- 普通本科（8分）+ 哥伦比亚大学硕士（QS Top 30，top档）→ 8 + 2（跨档提升）= 10分
  - ⚠️ 注意：本科含金量低时，即使硕士名校也应在总评中提示"本科院校较弱，硕士提升显著但本科基础需关注"
- 专科（5分）+ 专升本后普通硕士（同档）→ 5 + 0 = 5分（专升本视为同一学历的延续，不独立加分）

**以 A-S2 高校归一化校验结果为准，不采信候选人自述层次。**

#### 其他四个维度

| 维度 | 分值 | 详细标准 |
|------|------|----------|
| **经历丰富度** | 0-20 | 3+段相关经历且描述详尽 = 16-20; 2段经历 = 11-15; 1段经历 = 6-10; 无经历 = 0-5 |
| **技能覆盖度** | 0-20 | 多项技能有项目佐证 = 16-20; 有技能但部分无佐证 = 10-15; 仅罗列 = 5-9; 极少 = 0-4 |
| **稳定性** | 0-20 | 方向聚焦且经历连续 = 16-20; 转换合理 = 10-15; 频繁跳槽或方向混杂 = 5-9; 极不稳定 = 0-4 |
| **写作质量** | 0-20 | 结构清晰、量化具体、排版整洁、无错别字 = 16-20; 良好 = 11-15; 一般 = 6-10; 较差 = 0-5 |

### 输出格式

- 每个维度：分数 + 一句话评价
- **教育背景维度**须用表格展示计算过程（透明化）：
  - | 阶段 | 院校 | 层次 | 分数 | 权重/说明 |
  - | 本科 | {name} | {tier} | {n} | base分，权重65% |
  - | 硕士 | {name} | {tier} | +{n} | 加分 |
  - | **教育总分** | — | — | **{total}/20** | 上限20 |
- 总分 = 五个维度之和
- 总结段（2-3句）：概述优势与不足

1. **A-S1 已由代码写入** `A-parse/{filename}.analysis.md` 原始文本节

4. Append completion entry to A.log.md
5. Move to the next file

## Post-Processing: Deduplication

After ALL resumes are processed, perform cross-file duplicate detection:

### 精确匹配
- 姓名 + 手机号完全相同
- 姓名 + 邮箱完全相同
→ 标记为确认重复

### 模糊匹配
- 姓名相同/相似 + 同一学校 + 同一毕业年份
→ 标记为疑似重复，附匹配置信度

### 规则
- **永远不删除文件或修改 analysis.md** — 仅标记/标注
- 所有重复组记录在 A.alerts.md 中
